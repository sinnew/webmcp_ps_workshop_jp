🛠️ Chrome Extension & Built-in AI Field Guide

Essential architecture patterns, Manifest V3 permission rules, and critical gotchas for building WebMCP tool injectors and local Gemini Nano autonomous browser agents.

🔑

Manifest V3 Permissions: Track A vs. Track B

Compare the permission scope and architecture between declarative tool injection and full-stack side panel agent actuation:

Track A: Tool Injector (Fast-Track)

Declarative Content Script Injection

Injects WebMCP tool contracts (document.modelContext.registerTool) directly into target web pages. You inspect, validate schemas, and execute tools using Google's official WebMCP Tool Inspector Extension.

Track A manifest.json:
{
  "manifest_version": 3,
  "name": "WebMCP Injector",
  "version": "1.0",
  "content_scripts": [{
    "matches": ["https://*.rakuten.co.jp/*", "https://*.note.com/*", "http://localhost:*/*"],
    "js": ["tools.js"],
    "world": "MAIN",
    "run_at": "document_idle"
  }]
}
✅ Key Setting: "world": "MAIN" ensures tools register in the page's actual JS context rather than extension isolation.
Track B: Full-Stack AI Agent (Advanced)

Permissions ARE Mandatory

If your extension hosts an interactive chat UI in Chrome's Side Panel powered by local Gemini Nano and programmatically actuates the page:

Permission Meaning & For What
"sidePanel" Side Panel API: Displays sidepanel.html companion chat UI
"tabs" Tab metadata: Gets active tab ID to target tool execution
"scripting" Code injection: Runs tools in page via executeScript
host_permissions Domain authority: Allows side panel clicks to run scripts
Minimal Track B manifest.json:
{
  "manifest_version": 3,
  "name": "WebMCP AI Agent",
  "version": "1.0",
  "permissions": ["sidePanel", "tabs", "scripting"],
  "host_permissions": ["<all_urls>"],
  "background": { "service_worker": "sw.js" },
  "side_panel": { "default_path": "sidepanel.html" },
  "action": { "default_title": "Open Agent" }
}
⚠️ The `activeTab` Trap in Side Panels (Rule #12)
Clicking a button inside an extension Side Panel (e.g., "Submit Prompt") does NOT grant activeTab access to the page. activeTab only fires on direct browser chrome actions (toolbar icon click or context menu). If you don't declare "tabs", "scripting", and "host_permissions" in Track B, calling chrome.scripting.executeScript() will fail with a security violation!

Built-in AI (`LanguageModel`) Gotchas for Agents

1. Deprecated `window.ai` Namespace

Chrome 138+ standardized the API onto the top-level LanguageModel global. Do not use older tutorials referencing window.ai: 

// ❌ DEPRECATED (will fail in newer Chrome Canary):
const session = await window.ai.languageModel.create();

// ✅ MODERN STANDARD (Chrome 138+):
const session = await LanguageModel.create({
  initialPrompts: [{ role: 'system', content: 'You are an agent.' }]
});

2. Streaming Yields Delta Chunks (Append, Don't Overwrite!)

When consuming session.promptStreaming(), chunks are delta tokens, not the full accumulated response: 

let fullText = '';
for await (const chunk of session.promptStreaming(userQuery)) {
  fullText += chunk; // 👈 APPEND with += (Do NOT do output.textContent = chunk)
  chatOutput.textContent = fullText;
}

3. Freeing GPU Resources (`session.destroy()`)

Each active Gemini Nano session holds significant VRAM/DRAM on the attendee's laptop. Always destroy sessions on conversation reset: 

if (currentSession) {
  currentSession.destroy();
  currentSession = null;
}
⚡

WebMCP & Function Calling Bridge Gotchas

1. Calling WebMCP Tools from the Side Panel

When your Side Panel agent decides to call a WebMCP tool on the active page, you must specify world: "MAIN" in executeScript: 

// In sidepanel.js: Execute tool on the active tab
const [tab] = await chrome.tabs.query({ active: true, currentWindow: true });

const [{ result }] = await chrome.scripting.executeScript({
  target: { tabId: tab.id },
  world: 'MAIN', // 👈 MANDATORY! WebMCP document.modelContext lives in MAIN world!
  func: async (toolName, toolArgs) => {
    const tools = await document.modelContext.getTools();
    const targetTool = tools.find(t => t.name === toolName);
    if (!targetTool) throw new Error(`Tool ${toolName} not found`);
    return await targetTool.execute(toolArgs);
  },
  args: [toolCallName, toolCallArguments]
});

2. The 1.5 KB Token Budget Rule (Preventing Context Overflow)

Gemini Nano has a compact ~4K token context window. If your tool returns a raw 30 KB database record, the model will hallucinate or crash. Always strip outputs: 

// In tools.js: Lean, budgeted response
execute: async ({ query }) => {
  const rawResults = await fetch(`/api/search?q=${query}`).then(r => r.json());
  
  // ✅ Keep under 1.5 KB: Paginate and return only essential decision fields
  return JSON.stringify({
    total_matches: rawResults.length,
    items: rawResults.slice(0, 3).map(item => ({
      id: item.id,
      title: item.title,
      price_jpy: item.price,
      in_stock: item.inStock
    }))
  });
}

3. Form Submissions: Use `form.requestSubmit()` (Modern Web Guidance)

Avoid simulating robotic clicks on submit buttons or synthetic Enter key events. Modern Web Guidance recommends native form.requestSubmit(), which properly runs HTML form validation and triggers framework handlers: 

const form = input.closest('form');
if (form && typeof form.requestSubmit === 'function') {
  form.requestSubmit(); // ✅ Baseline standard: validates and submits cleanly
} else {
  input.dispatchEvent(new KeyboardEvent('keydown', { key: 'Enter', bubbles: true }));
}

4. Graceful Cancellation with `AbortSignal` (MWG Standard)

WebMCP passes { signal } as the second argument to execute. Forward it to in-flight fetch() requests so cancelled agent queries don't waste network resources: 

execute: async ({ query }, { signal }) => {
  if (signal?.aborted) return 'Aborted';

  // ✅ Forward signal to fetch: cancels immediately if user stops the agent
  const res = await fetch(`/api/search?q=${encodeURIComponent(query)}`, { signal });
  const data = await res.json();
  return JSON.stringify(data.slice(0, 3));
}

5. Native `<dialog>` for Human-in-the-Loop Confirmation

Do NOT build ad-hoc <div> overlays with custom z-index hacks. MWG mandates native <dialog> with .showModal() for built-in focus trapping, top-layer rendering, and verified event.isTrusted clicks: 

const dialog = document.getElementById('hitl-dialog');
dialog.showModal(); // ✅ Native top-layer modal, traps focus, supports Escape

confirmBtn.addEventListener('click', (event) => {
  if (!event.isTrusted) return; // 🛡️ Verifies genuine physical user click!
  dialog.close('confirmed');
}, { once: true });

6. The "Ghost Browser" Trap: Why Client UI Reflection is Mandatory

Do not build WebMCP tools that bypass the DOM and silently invoke backend APIs. In interactive co-browsing, the viewport is the shared mental canvas between the human and the agent:

Example (Account Registration): If an agent registers an account purely via fetch('/api/register'), the on-screen form remains blank. If backend validation fails (e.g., password complexity, duplicate email), the user never sees inline field errors or red highlights. Crucially, Chrome's native Password Manager, Autofill, and Passkey creation are completely bypassed because they listen to standard DOM events and form submissions (form.requestSubmit()).

Architectural Rule:
• Frontend WebMCP (DOM & Client State Sync): Mandatory for interactive co-browsing (form completion, catalog filters, seat selection, checkout) so users see live validation, progress, and visual feedback.
• Headless Backend AI: Suitable only for offline, asynchronous, or batch tasks (overnight reconciliation, bulk indexing) where no human is actively viewing the screen.
