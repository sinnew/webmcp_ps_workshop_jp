CRITICAL: Chrome 155.0.8052.0+ Breaking Change (`executeTool()` Input Arguments)

W3C WebMCP PRs #246 & #251 • Landed in Chromium 155.0.8052.0
Chrome 155.0.8052.0+ Spec

Following W3C WebMCP pull requests #246 and #251, the input arguments parameter for document.modelContext.executeTool(toolName, inputArgs) has changed from a serialized DOMString (JSON string) to an optional JavaScript object (object) starting in Chrome 155.0.8052.0.

❌ Legacy (Chrome ≤ 154) • DOMString Input

Serialized JSON String Required

Previously, callers had to manually JSON.stringify() arguments before calling executeTool(), and tool handlers had to JSON.parse() the incoming string: 

// ❌ Legacy Chrome 154 Caller (DOMString)
const res = await document.modelContext.executeTool(
  'filter_products',
  JSON.stringify({ category: 'shoes', maxPrice: 12000 })
);
✅ Modern (Chrome 155.0.8052.0+) • JS Object Input

Native JavaScript Object Argument

Starting in Chrome 155.0.8052.0, pass a native JavaScript object directly as the second argument (or omit it if the tool takes no parameters): 

// ✅ Chrome 155.0.8052.0+ Caller (PRs #246 & #251)
const res = await document.modelContext.executeTool(
  'filter_products',
  { category: 'shoes', maxPrice: 12000 }
);
🛡️ Universal Defensive Pattern (Supports Both Chrome 154 & Chrome 155.0.8052.0+)

During the Chrome 154–156 Origin Trial transition window, use this defensive normalization helper inside every Track A tool's execute(args, options) handler and Track B agent invoker so your code works seamlessly on both Chrome 154 and Chrome 155+: 

// Inside your registerTool({ execute: async (args, options) => { ... } })
execute: async (args, options) => {
  // Normalizes both Chrome 155+ JS Objects AND legacy Chrome 154 DOMStrings
  const params = typeof args === 'string'
    ? (args.trim() ? JSON.parse(args) : {})
    : (args || {});

  // Safe to access properties directly:
  const { category = 'all', maxPrice = 50000 } = params;
  return { status: 'OK', category, maxPrice };
}

1. Manifest V3 Architecture: Track A vs. Track B

Compare permission scope and execution world between declarative tool injection (Track A) and full-stack Side Panel agents (Track B).
Track A: Tool Injector (Fast-Track)

Declarative Content Script Injection

Injects WebMCP tools (await document.modelContext.registerTool) directly into the web application. Zero host permissions required.

Track A manifest.json:
{
  "manifest_version": 3,
  "name": "WebMCP Tool Injector (Track A)",
  "version": "1.0",
  "content_scripts": [{
    "matches": ["https://*.example-store.com/*", "http://localhost:*/*"],
    "js": ["tools.js"],
    "world": "MAIN",
    "run_at": "document_idle"
  }]
}
✅ Mandatory Rule: "world": "MAIN"
Content scripts run in an isolated world by default where document.modelContext is invisible to the page and browser agents. Setting "world": "MAIN" registers tools in the page's actual JavaScript context.
Track B: Full-Stack AI Agent (Advanced)

Side Panel + Local Gemini Nano Agent

Hosts a persistent Side Panel chat UI powered by local Gemini Nano (LanguageModel) that inspects and invokes WebMCP tools on the active tab:

Permission Why It Is Required
"sidePanel" Side Panel UI: Renders persistent sidepanel.html agent interface
"tabs" Active Tab Resolution: Resolves target tabId for tool discovery
"scripting" Cross-World Bridge: Executes executeTool(name, argsObject) in MAIN world
host_permissions Persistent Access: Side Panel clicks do not grant temporary activeTab
Minimal Track B manifest.json:
{
  "manifest_version": 3,
  "name": "WebMCP Side Panel Agent (Track B)",
  "version": "1.0",
  "permissions": ["sidePanel", "tabs", "scripting"],
  "host_permissions": ["<all_urls>"],
  "side_panel": { "default_path": "sidepanel.html" }
}
⚠️ Critical Gotcha: Why "activeTab" Alone Fails in Side Panels
In Chrome Extensions, clicking a button inside a Side Panel does not count as a user gesture on the host web page. If your manifest only lists "activeTab" without "host_permissions": ["<all_urls>"], calling chrome.scripting.executeScript from the Side Panel throws: Error: Cannot access contents of the page. Extension manifest must request permission to access the respective host.

2. Built-in AI (Gemini Nano) & WebMCP Execution Gotchas

Essential runtime patterns for Chrome's Prompt API (LanguageModel) and WebMCP tool orchestration.

1️⃣ Unified LanguageModel Namespace

Older tutorials reference window.ai.languageModel. Always use the standardized global LanguageModel API (with fallback for older builds): 

const LM = self.LanguageModel
  || self.ai?.languageModel;
const avail = await LM.availability();
if (avail !== 'unavailable') {
  const session = await LM.create();
}

2️⃣ promptStreaming() Yields Delta Chunks

In modern Chrome Canary builds, session.promptStreaming(prompt) yields incremental delta chunks (not accumulated strings). Use += to accumulate: 

let fullReply = '';
const stream = session.promptStreaming(prompt);
for await (const chunk of stream) {
  fullReply += chunk;
  outputEl.textContent = fullReply;
}

3️⃣ Async registerTool() & AbortSignal

In Chrome 154+, document.modelContext.registerTool() returns a Promise. Always await registration and pass an AbortSignal for clean SPA route unmounting: 

const controller = new AbortController();
await document.modelContext.registerTool({
  name: 'get_user_devices',
  description: 'Fetches registered devices',
  inputSchema: { type: 'object', properties: {} },
  execute: async (args) => ({ devices: [] })
}, { signal: controller.signal });

3. Modern Web Guidance: Client UI Synchronization Rules

Avoid the "API-First Trap" — when an agent invokes a WebMCP tool, the visible DOM must update in real time.
❌ Anti-Pattern: Silent Backend Mutation

The API-First Trap

Calling fetch('/api/cart/add') inside execute() without updating the client state store leaves the user staring at an empty cart badge and stale page UI.

✅ Best Practice: View Transitions + State Sync

Synchronized Client Actuation

Dispatch actions to your client store (Redux/Zustand/React state) wrapped in document.startViewTransition() and return an Enterprise Return Envelope ({ status, activeState, workflowGuidance, items }).
